## Security and acceptance invariants
1. Discovery/IP/QR and `pairing.phone-proof` are not a native input grant. Verified DTLS exporter, both direction-correct certificate fingerprints, SCTP stream, pinned phone key and host-owned nonce must originate from the **same established native association**; Android must verify pinned host identity. Test fixture `nativeAuthority=false` never becomes runtime evidence.
2. Local approval must originate from an OS-local Win11 user-session callback for the exact device/session/channel/nonce/deadline; renderer, network and JS cannot mint `NativeApprovalReceipt` or `VerifiedChannelEvidence`. Deny on lock, UAC secure desktop, user switch, expiry, revoke, transport loss, release failure.
3. Only a real native backend may dispatch after all gates. Track held input; revoke and attempt all key/button releases before exit/reconnect. Keep `DisabledMissingNativeAuthority`, `DisabledInput`, discovery/capture/input OFF until the verified integration is actually complete.
4. No force push, no destructive reset, no stage of foreign dirty paths, no production firewall change, no public listener, no signing/install/package without explicit owner approval. Strict TS/no `any`, SRP/SOLID, Rust Result errors and adversarial tests.
5. Worker source completion requires scoped diff + tests with command/exit/run IDs + own worklog + commit/push + remote 0/0; **functional** M1 acceptance requires real Android/Win11 E2E A01–A17 and artifact provenance. Historical tests are not current-run PASS.
