## Protocol decision / dependency boundary
- SELECT TLS 1.3 over exact RFC1918 IPv4-bound TCP; host rustls 0.23.x with reviewed crypto provider and certificate provision + Android platform JSSE SSLSocket/TLSv1.3 with explicit X.509 SPKI or certificate SHA-256 pin. Rationale: TLS TCP is byte-stream, native socket verification and JSSE interoperability work without WebRTC signaling/STUN/ICE/SCTP or DTLS exporter API exposure; TLS handshake completion gives cryptographic peer/server evidence, unlike synthetic transcript/hash. DTLS/WebRTC has larger dependency/surface and missing Android native integration; plain TCP invalid.
- TLS handshake must be verified *in process on the live socket*, with exact private local address and OS-selected route revalidation; timeout, length caps and single bounded association; no wildcard or plaintext listener. Android must verify host public key against an **independently trusted out-of-band** pin (QR may carry pin as hint only when physically verified); do not disable platform trust indiscriminately or accept unknown certificate. Host certificate/key persistent storage and TLS provider dependency need explicit owner security approval. Do not introduce rustls/rcgen/ring/other package or INTERNET release manifest permission until authorized. Existing tools can implement protocol frame codecs, native authorization components and hostile tests without acquiring new packages.
- Enrollment separate from TLS: Android Keystore-backed persistent nonexportable Ed25519 key *only if supported on verified API devices* (deny on unsupported provider); independently locally approved enrollment record on host persistent encrypted user-scoped store; proof signs domain-separated transcript of host nonce, pinned verified TLS leaf fingerprint/SPKI, observed socket endpoints, nonzero monotonic host epoch + Android nonce; host verifies against locally enrolled key and consumes nonce once. TLS certificate possession does not equal enrolled-phone identity, signature does not equal OS grant.
- Host MUST derive fingerprint/epoch/endpoints from native TLS socket and native counter, never caller/renderer/QR. Platform JSSE exposes peer X509 cert; crypto transcript can bind cert fingerprint with both nonces/association ID signed by host/phone inside TLS, but cannot rely on an unimplemented exporter. Both sides compare exact deterministic encoding. TLS identity pin TOCTOU and DNS rebind denied via literal addresses + post-handshake same-peer checks. Time via monotonic clock for ephemeral leases, reject epoch reuse, session replay, revocation, OS lock, half-open and partial-send failures. Restart requires fresh local consent; persistent enrollment does not persist a session/input lease.
