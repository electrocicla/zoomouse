## Frozen R18 HOST/Android binary agreement
- Native TLS application frame is `u16 length BE` + payload `1..4096`. Never pass length/trust fields from QR/JS.
- Host challenge payload EXACT 118 bytes: `0x01 version | 0x01 challenge-tag | epoch u64BE [8] | verified TLS leaf cert SHA256[32] | host IPv4[4] | host port u16BE[2] | phone IPv4[4] | phone port u16BE[2] | hostNonce[32] | enrolledEd25519PhonePublicKey[32]`.

- Phone response payload EXACT 98 bytes: `0x01 version | 0x02 response-tag | clientNonce[32] | Ed25519Signature[64]`. Host must verify the same live verified TLS socket, local enrollment revision and one-time host nonce/epoch; no plaintext fallback. HOST sent explicit ABI confirmation 2026-11-20 17:34:25Z and R18 parent 17:37:38Z.
- Android rejects epochs outside positive signed 64-bit range; host monotonic Rust `AtomicU64` presently resets to zero on host restart. A stable leaf pin + Android persisted high-water means subsequent legitimate host reboot associations may remain denied indefinitely; this is a **fail-closed restart/availability blocker**, not acceptance. Required separate owner-approved persistent host epoch/store or authenticated new-boot generation and explicit re-enrollment protocol before A1/A2.
- Host Rust source `crates/host/src/tls_association.rs` creates **no** actual native rustls socket, no approved certificate store, no persistent host enrollment, and no production constructor for verified host evidence. Matching source codec bytes alone are not a live interoperable channel.
