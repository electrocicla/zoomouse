# Zoomouse M2-B — media admission foundation (NOT an H.264 encoder)

**Status: source foundation, default fail-closed.** Standalone Rust crate with deterministic geometry/format/clock/backpressure and trusted-host authorization gates. The Windows `UnavailableD3d11MediaFoundation` adapter accepts a borrowed `zoomouse_capture::native::GpuFrame` only to validate metadata and current authority and returns `BackendUnavailable` **without copying/encoding a single pixel**. No GPU crop/scale, NV12 conversion, hardware encoding, network/WebRTC, Android decode, user-approved physical frame or performance acceptance is implemented.

## Boundary and call graph

`WgcCapture::poll_frame()` (M2-A) -> borrowed `GpuFrame` with IDirect3DSurface, owning WGC frame, local source ID, grant generation, sequence, QPC-relative 100ns and content size -> Windows native adapter constructs `FrameDescriptor` -> `MediaSession::admit` checks current trusted device/session/generation/source, dimensions, known BGRA8 and **host-verified** SDR BT.709 limited color space, even chroma-aligned ROI, undistorted output aspect and 1080p max profile, frame age/ordering, 1-3 bounded in-flight slots -> `MediaSession::verify_output` rechecks grant -> **hard fail** `BackendUnavailable`.

`SourceTag` / `CaptureScope::new` / UI state / peer packet are NOT authorizations. Positive `MediaAuthorization` must reside in the independently authenticated interactive Windows host and check current local grant, device and session identity, grant generation, source/selection, locked desktop, revocation, sleep and emergency stop. `DenyAll` is default. Native integrations must call `revoke()` immediately on shutdown, source close, resize, session change, lock, GPU device loss, host stop and network disconnect. A size change is a source reset, not permission to reinitialize or automatically pick a new source.

**Temporal contract:** QPC-relative **100-ns** clock, not Unix time. Host must supply same-domain current QPC converted to 100ns without wall-clock conversion, reject future >1ms, stale >500ms, nonmonotonic sequence or timestamp. Reset timing only by creating a new explicitly authorized session. Slot pool enforces backpressure via RAII; this is an admission bound, not a GPU texture allocator. No queued frames may survive revocation and output still needs a fresh host authorization directly before transport.

**Color contract:** WGC creates `B8G8R8A8UIntNormalized` GPU surfaces, but neither that DXGI format nor a screenshot proves SDR BT.709 limited/alpha handling. The future host/interop must explicitly verify source SDR/HDR output characteristics and map BGRA to NV12 with correct matrix, range, chroma siting and alpha. Unknown, HDR, BT.601 and unapproved input formats fail closed; never silently tone-map HDR to SDR. Mixed DPI/rotation and capture content space remain M2-C physical QA gates.

## Exact native implementation gates (parent/assigned integration owner)

1. Trusted Tauri/native host binds same D3D11 device used to create `IDirect3DDevice` for WGC and an `ID3D11Device`/`ID3D11DeviceContext`, with GPU/device-loss synchronization and a bounded pool of <=3 same-device output textures. Use WinRT/Direct3D interop to obtain `ID3D11Texture2D` from `IDirect3DSurface` **only while WGC frame remains alive**. Verify texture desc, array slice, BGRA8 pixel format and device identity; reject cross-device, protected/occluded/revoked state. No CPU readback as fallback.
2. Implement real GPU crop/scale and BGRA-to-NV12 via D3D11 video processor or shader, with even ROI and output dimensions, verified SDR matrix/range. Track device loss/reinitialization, resize and invalid ROI as drop/re-consent boundaries; include output texture accounting/fences, rather than using the pure slot count as proof of GPU memory bounds.
3. Discover and negotiate *actual* D3D11-aware Media Foundation H.264 encoder transform (MFT): DXGI device manager / `MF_SA_D3D11_AWARE`, NV12 input attributes, H.264 output and bitrate/fps/profile, `MFCreateDXGISurfaceBuffer` or equivalent MF GPU surface handoff, timestamps/duration, dynamic format changes, async MFT drain/flush, keyframe/annex-B/AVCC packetization and error paths. If unavailable, report explicit encoder unavailable; no hidden software/CPU fallback.
4. Bind H.264 packets to a current trusted grant *after* completion; keep DTLS/SRTP WebRTC sender device/session/generation-bound, drop all pending packets on revoke, and use backpressure without stale-frame queue accumulation. Parent integrates transport and Android MediaCodec/WebRTC receiving/rendering separately. No open listener, relay, WAN or Session 0.
5. Physical receipts: signed current Windows process/graphics adapter, owner HWND and OS picker, real texture/encoder MFT enumeration and hardware capability, real H.264 output decode on physical Android, source resize/device loss, HDR, negative-origin/mixed-DPI rotation, revoke while in-flight, p95 glass-to-glass latency and GPU memory/CPU use. Mark M2 gate NOT ACCEPTED until verified.

No shared Cargo root/lockfile, host, capture, Tauri, protocol or mobile source was edited in this worker scope. Build the crate independently with `cargo test --manifest-path crates/media/Cargo.toml`, `cargo fmt --manifest-path crates/media/Cargo.toml -- --check`, `cargo check --manifest-path crates/media/Cargo.toml`, and strict Clippy on Windows. `Cargo.lock` generated inside crate is owned.

References: Microsoft Learn *Direct3D-Aware MFTs*, `MF_SA_D3D11_AWARE`, *Supporting Direct3D 11 Video Decoding in Media Foundation* (device-manager patterns, not evidence of current host hardware encoder support).
