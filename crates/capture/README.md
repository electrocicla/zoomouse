# Zoomouse capture — M2-A user-session WGC foundation

**Status:** standalone source module only. Not linked into `crates/host` or Tauri; no approved/observed capture session, GPU device, physical frame, crop, encoder, WebRTC transport, or Android decoder. The default `DenyAll` authorizer prevents any native capture. Do not advertise M2 video readiness from a successful source check.

## Integration contract for parent (M1/M2-B/M2-C)

1. Add `zoomouse-capture = { path = "../capture" }` to `crates/host/Cargo.toml` **only as a separately authorized parent/host integration**, and Tauri UI integration as appropriate; M2-A does not edit shared manifests. Cargo crate can be checked on its own with `cargo test --manifest-path crates/capture/Cargo.toml` and `cargo check --manifest-path crates/capture/Cargo.toml --target x86_64-pc-windows-msvc`.
2. In trusted **interactive user-session** host code implement `CaptureAuthorization::permits(&CaptureScope)` against authenticated device ID, current session, local grants, matching generation, foreground/revocation/lock/sleep state. Unknown or stale => false. Never implement as a remote-provided boolean, a renderer JS flag, persisted preference or source ID. Re-check after each frame; call `Cancellation::cancel()` and `WgcCapture::revoke()` when a session ends. The host's emergency-stop must close capture, input and transport together.
3. Only a locally initiated Tauri action provides a real **native owner HWND** to `WgcCapture::select_local_source(hwnd).await`. It launches the Windows `GraphicsCapturePicker`, NOT `IGraphicsCaptureItemInterop::CreateForWindow/Monitor` with a remote handle. The returned `SourceId::UserPicked` is informational; OS picker does not supply display/window classification. No selection is resumed automatically after restart.
4. Provide a real WinRT `IDirect3DDevice` backed by the **same** session-local D3D11 device for `start(&device)`. This foundation deliberately does not choose GPUs, create a device, or perform CPU capture. `poll_frame()` returns an optional `GpuFrame { metadata, surface }` with an owned WGC frame lifetime: M2-B must synchronously consume/copy GPU texture to its own bounded pool before dropping frame, crop on GPU, encode H.264 and use separately authenticated WebRTC DTLS/SRTP. `FrameMetadata::qpc_100ns` is Windows QPC-relative timing, not wall clock.
5. WGC `Closed` and `FrameArrived` handlers use a free-threaded frame pool. On source resize, the pool is recreated and the transitional frame dropped; on revocation/cancel/source close, references are closed. Protected windows/secure desktop are never bypassed. WGC border is **not disabled**. Native host must show its own persistent capture indicator, and explicitly distinguish capture-paused/disabled from stream-in-progress.
6. For M2-C use physical `GetCursorPos` with a PerMonitorV2-aware host, trusted desktop source bounds and rotation. `cursor_to_frame` is pure and rejects points outside source half-open bounds (incl. negative origins). Logical CSS/widget coordinates may only be transformed with explicit `DpiMapping`; never apply DPI conversion twice. Source content rectangles/rotation/occlusion require physical verification.

## Evidence and security limitations

- `CaptureAuthorization` is a trusted-host contract, **not** a built-in cryptographic approval source; no production host adapter is yet integrated. A malicious implementation of the trait inside the host could bypass it. Android/UI/network messages must never instantiate authority.
- Only a real Windows 11 user session, OS picker, active D3D11 device and observed native frame proves the WGC path. Compiler success, geometry tests or a picked item alone do not.
- No Session 0 service, elevation, UAC/secure desktop capture, device enumeration, remote HWND/monitor injection, automatic repick, frame serialization, video networking, image saving or clipboard.
- Validation gates for parent: deny-before-consent and after-revocation on a real phone/host; OS picker cancellation; locked desktop; picker owner HWND; source close/resize; HDR/color/rotation; multi-monitor mixed-DPI and negative origins; GPU device lost and race testing; freeze/sleep/stop; frame latency and memory; M2-B codec/WebRTC E2E and M2-C follow/zoom physical QA.
