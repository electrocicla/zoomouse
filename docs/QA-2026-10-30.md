## Defects found and fixed in this QA pass

1. **QR vs IP**: QR previously opened the IP input. Now they are separate, clearly labeled demo flows.
2. **Cursor freeze**: follow OFF previously recentered the CSS crop at 50/50. Crop anchor now freezes; follow ON resumes from the current simulated cursor.
3. **Keyboard access**: simulated video region now accepts focus and arrow keys.
4. **Inert enlarge button**: fullscreen-like preview action now toggles a larger video viewport and accessible state.
5. **Incorrect click simulation**: left/right demo clicks previously moved the cursor. They now provide explicit action feedback without dispatching real input.
6. **Panel order coupling**: changing panel order previously toggled the left-handed mode. Both preview options now have independent state.
7. **Host approval status**: static "waiting" status now reflects demo permission and capture changes.
8. **Unexplained help entries**: planned controls now clearly show M3 status when selected.
9. **Touchpad drag**: preview now updates cursor through pointerdown and pressed pointermove rather than pointerdown alone.
10. **Lint gap**: added ESLint + TypeScript/React-hooks rules, including errors for `any` and non-null assertions; replaced the one unsafe assertion with an explicit default host.
11. **Automated UI/security coverage**: added jsdom interaction tests and protocol defensive-validation cases.

## Gaps and next implementation gates

**M1 release blockers:** scaffold and compile Android React Native New Architecture and Windows Tauri/Rust user-session host; implement device identity and user-approved pairing; validate network discovery (mDNS/IP/QR) and authenticated input over WebRTC. Never use preview authorization state as a real access-control boundary. Define key-up cleanup, stale packet rejection and per-device revocation before sending input to Windows.

**M2 release blockers:** select Windows capture source, implement GPU crop/scale and H.264 encoding, use Android native WebRTC decoder, test crop transforms on monitor edges and mixed DPI; instrument glass-to-glass latency and GPU load. CSS scale is not a production crop algorithm.

**M3 release blockers:** implement all screenshot settings in actual mobile app with per-device persistence; validate keyboard modifiers/IME, media/browser controls, settings accessibility and localization.

**M4 release blockers:** separate security and relay review before TURN/signaling, carrier NAT testing and internet exposure.

## Engineering constraints retained

Strict TypeScript (no `any`), small interfaces, single-responsibility modules, stable versioned transport, least-privilege Windows consent, explicit demo labels and no fake performance claims. Keep input/control and media pipelines testable independently.
